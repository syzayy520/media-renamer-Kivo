# 默认假设清单

> 阶段 0：项目理解与澄清
> 项目：media-renamer-Kivo
> 日期：2026-06-08

---

## 一、默认专业假设

以下假设是专业软件团队在缺乏用户明确指示时的默认立场。每条假设均说明理由和假设错误的影响。

---

### 1. MVP 优先 Windows 10/11

| 项目 | 内容 |
|------|------|
| **假设** | MVP 仅支持 Windows 10 及以上版本 |
| **理由** | Windows 是国内媒体收藏用户的主流平台；跨平台增加测试和打包复杂度；先做好一个平台再扩展 |
| **假设错误的后果** | 如需 macOS/Linux，MVP 交付延迟约 2-4 周 |
| **需用户确认** | 否（任务书已隐含） |

---

### 2. MVP 不联网

| 项目 | 内容 |
|------|------|
| **假设** | MVP 所有功能离线可用，不连接 TMDb/TVDB/AniDB 等元数据源 |
| **理由** | 减少外部依赖、隐私风险、网络故障影响；降低 MVP 复杂度；文件名解析可覆盖多数场景 |
| **假设错误的后果** | 如需联网刮削，需要增加约 3-5 个功能族，延迟 2-4 周 |
| **需用户确认** | 否（任务书已明确） |

---

### 3. 只改视频文件名，不动目录

| 项目 | 内容 |
|------|------|
| **假设** | MVP 只改视频文件名（含扩展名），不移动文件、不改父目录、不创建新目录 |
| **理由** | 最小化风险范围；目录整理是独立功能，复杂度高，应单独迭代 |
| **假设错误的后果** | 如需移动文件，需增加目录操作族、冲突检测扩展到目录级别 |
| **需用户确认** | 否（任务书已明确） |

---

### 4. 伴随文件不改名

| 项目 | 内容 |
|------|------|
| **假设** | 字幕（.srt/.ass 等）、海报（.jpg/.png 等）、NFO 文件不自动改名 |
| **理由** | 避免意外破坏播放器/刮削器的文件关联；伴随文件命名规则复杂（一对多、多对一） |
| **假设错误的后果** | 如需联动改名，需增加伴随文件映射族，增加约 1-2 周 |
| **需用户确认** | 否（任务书已明确） |

---

### 5. 低置信度项默认不改名

| 项目 | 内容 |
|------|------|
| **假设** | 解析置信度低于阈值的项目不自动执行改名，全部进入人工确认页面 |
| **理由** | 安全优先；误改名比不改名危害更大；人工审核是最后的安全阀 |
| **假设错误的后果** | 如允许自动改名低置信度项，误改名风险剧增 |
| **需用户确认** | 否（任务书已明确） |

---

### 6. 冲突项阻断执行

| 项目 | 内容 |
|------|------|
| **假设** | 检测到任何冲突（目标路径冲突、重名、路径过长、非法字符等）时，阻断本次执行任务，不允许部分执行 |
| **理由** | 部分执行会增加回滚复杂度；用户应一次性处理所有冲突 |
| **假设错误的后果** | 如需允许部分执行，回滚逻辑复杂度增加约 50% |
| **需用户确认** | 否（任务书已明确） |

---

### 7. 回滚记录持久化

| 项目 | 内容 |
|------|------|
| **假设** | 回滚所需信息（before/after 映射、任务 ID、时间戳、状态）持久化到本地数据库 |
| **理由** | 内存中的数据在崩溃或关闭后丢失，无法回滚 |
| **假设错误的后果** | 崩溃后无法回滚，文件可能永久改名，用户数据风险极高 |
| **需用户确认** | 否（任务书已明确） |

---

### 8. 测试隔离于 sandbox fixtures

| 项目 | 内容 |
|------|------|
| **假设** | 所有测试使用 `examples/fixtures/sandbox/` 下的模拟文件，禁止操作真实媒体目录 |
| **理由** | 防止测试过程中的误操作破坏用户数据 |
| **假设错误的后果** | 用户媒体文件被意外修改/删除/损坏 |
| **需用户确认** | 否（任务书已明确） |

---

### 9. 单次扫描支持大数量

| 项目 | 内容 |
|------|------|
| **假设** | 单次扫描支持 10,000+ 文件，UI 采用虚拟滚动处理大列表 |
| **理由** | 大型媒体库常见数千文件；虚拟滚动是桌面应用处理大列表的行业标准 |
| **假设错误的后果** | 如果文件数量超出设计上限，UI 卡顿或崩溃 |
| **需用户确认** | 是（建议确认预期规模） |

---

### 10. 动漫与剧集按文件名模式区分

| 项目 | 内容 |
|------|------|
| **假设** | MVP 通过文件名中的特征（组名标记、`[字幕组]` 格式、分辨率标记位置、命名后缀特征）区分动漫和真人剧集 |
| **理由** | 无网络元数据支持时，文件名是唯一信息源 |
| **假设错误的后果** | 部分动漫被误判为剧集（或反之），标记低置信度进入人工确认 |
| **需用户确认** | 否 |

---

### 11. MVP 单一深色主题

| 项目 | 内容 |
|------|------|
| **假设** | MVP 默认深色主题，不做浅色主题切换 |
| **理由** | 专业工具标准；减少设计工作量；深色更适合长时间使用 |
| **假设错误的后果** | 如强制需要浅色主题，需增加主题系统族 |
| **需用户确认** | 是 |

---

### 12. MVP 中文界面

| 项目 | 内容 |
|------|------|
| **假设** | MVP 默认中文界面，不做 i18n |
| **理由** | 目标用户以中文用户为主；减少 MVP 复杂度 |
| **假设错误的后果** | 如需英文界面，需增加 i18n 基础设施 |
| **需用户确认** | 是 |

---

### 13. 数据库使用 SQLite

| 项目 | 内容 |
|------|------|
| **假设** | MVP 使用 SQLite 保存任务、预览、执行结果、回滚记录和审计日志 |
| **理由** | 零配置、嵌入式、无需服务进程；适合桌面应用；生态成熟 |
| **假设错误的后果** | 更换数据库需重写持久化层 |
| **需用户确认** | 否（阶段 2 技术选型时不锁定） |

---

### 14. 文件系统操作权限

| 项目 | 内容 |
|------|------|
| **假设** | 用户运行软件时，对目标目录有读写权限 |
| **理由** | 桌面应用运行在用户权限下，通常能操作用户自己的媒体目录 |
| **假设错误的后果** | 权限不足导致部分文件改名失败，标记为失败项 |
| **需用户确认** | 否 |

---

### 15. 扫描递归所有子目录

| 项目 | 内容 |
|------|------|
| **假设** | 扫描默认递归所有子目录，不设深度限制 |
| **理由** | 媒体库通常按"分类/片名/季"多层嵌套，限制深度会遗漏文件 |
| **假设错误的后果** | 如果用户有极深嵌套目录，可能扫描到非目标文件 |
| **需用户确认** | 是 |

## 三、整树家谱模式默认假设

| # | 假设 | 理由 |
|---|------|------|
| 1 | 功能族按领域拆分：scan/parse/rename/rollback/audit/config/ui | 领域驱动，边界清晰 |
| 2 | 跨族通信通过接口契约 + 依赖注入 | 解耦，可测试 |
| 3 | 入口文件仅 re-export，不超过 30 行 | 薄入口 |
| 4 | 测试目录镜像源码模块树 | 可追溯 |
| 5 | 每个文件只承担一个最小职责 | 整树家谱核心 |
| 6 | 禁止万能 utils、上帝 service、flat helper | 防止结构腐化 |
| 7 | shared/ 按子功能族拆分（如 shared/path、shared/result） | 有组织的共享 |

## 四、UI 默认假设

| # | 假设 | 理由 |
|---|------|------|
| 1 | 默认窗口 1280×800 | 适应 1080p 及以上屏幕 |
| 2 | 文件数 > 100 时启用虚拟滚动 | 性能保证 |
| 3 | 预览表格以"状态"列排序（冲突 > 低置信度 > 正常） | 风险优先 |
| 4 | 不自动保存未确认的修改 | 避免用户困惑 |
| 5 | Toast 通知非侵入式，自动消失 | 不影响当前操作 |

## 五、风险假设汇总

以下假设如果错误，对项目影响较大，需重点关注：

| 风险假设 | 等级 | 缓解 |
|---------|------|------|
| 单次扫描文件量远超 10,000 | MEDIUM | 虚拟滚动 + 分页 + 性能测试 |
| 用户媒体目录无写权限 | LOW | 扫描阶段检测权限 |
| 文件名编码异常（非 UTF-8） | MEDIUM | 编码检测 + 降级处理 |
| Windows 路径长度限制（260字符） | HIGH | 扫描阶段检测并标记 |
| 用户期望联网刮削元数据 | LOW | 文档说明 + V1 路线图 |
