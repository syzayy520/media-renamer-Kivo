# 项目理解文档

> 阶段 0：项目理解与澄清
> 项目：media-renamer-Kivo
> 日期：2026-06-08

---

## 一、项目目标复述

media-renamer-Kivo 是一个桌面软件，用于扫描本地媒体目录中的视频文件（电影、电视剧、动漫、特别篇等），通过解析文件名中的信息（片名、年份、季集号、分辨率、编码、音轨等），按照可配置的命名模板自动生成重命名预览，经用户人工确认后安全执行文件重命名，并记录完整审计日志，支持按任务回滚。

该项目的核心价值在于：**将媒体库中混乱、不规范的文件名批量整理为统一、规范的命名格式**，方便后续管理、刮削和播放器识别，同时以极高的安全性避免误操作。

---

## 二、产品定位

- **定位**：专业本地媒体文件重命名桌面工具
- **目标用户**：拥有本地媒体库的用户（Plex/Jellyfin/Emby/Kodi 用户、PT 用户、媒体收藏者）
- **平台**：MVP 优先 Windows 10/11
- **核心场景**：用户下载或整理媒体文件后，文件名混乱（如 `[Group] Series Name - 01 [1080p].mkv`），需要通过工具批量统一重命名为规范格式（如 `Series Name - S01E01.mkv`）
- **产品气质**：专业、安全、克制、可信赖 — 不做花哨的玩具，做严肃的生产力工具

---

## 三、核心用户价值

1. **规范化命名**：将混乱文件名统一为媒体服务器识别的标准格式
2. **安全性**：默认 dry-run、多重冲突检测、低置信度拦截、二次确认、可回滚
3. **可审计**：每次改名操作完整记录 before/after，支持按任务回滚
4. **可控性**：预览 → 审核 → 确认 → 执行 → 回滚，全程可控
5. **离线可用**：MVP 不依赖网络，基于本地文件名解析规则

---

## 四、MVP 初步边界

### 包含

| 类别 | 说明 |
|------|------|
| 媒体扫描 | 扫描指定目录，仅识别视频文件（.mkv/.mp4/.avi 等 13 种） |
| 文件名解析 | 从文件名中提取标题、年份、季集、分辨率、来源、编码、音轨等信息 |
| 分类识别 | 区分电影、电视剧、动漫、特别篇、SP、OVA、NCOP、NCED、Extras |
| 重命名预览 | 按模板生成新名称，展示 before/after 对比 |
| 低置信度标记 | 不确定的解析结果标记为低置信度，默认不改名，需人工确认 |
| 冲突检测 | 目标路径冲突、重名、路径长度、非法字符、权限等检查 |
| 安全执行 | dry-run 预演 → 预览确认 → 二次确认 → 执行 |
| 审计日志 | 记录每次改名的 before/after 映射、规则命中来源、执行时间、状态 |
| 任务回滚 | 支持按任务将已改名文件恢复为原名 |
| 崩溃恢复 | 持久化任务状态，支持从审计日志恢复 |

### 不包含（MVP 不做）

| 类别 | 说明 |
|------|------|
| 联网刮削 | 不连接 TMDb/TVDB/AniDB 等元数据源 |
| 目录整理 | 不移动文件夹、不自动创建季目录结构 |
| 字幕联动 | 不自动重命名字幕文件（.srt/.ass 等） |
| 海报/NFO | 不自动重命名海报、fanart、NFO 文件 |
| 多平台 | MVP 仅 Windows 10/11 |
| 批量模板高级配置 | 先提供默认模板，V1 再增强 |
| 自动更新 | V1 考虑 |
| 深色/浅色主题切换 | MVP 默认一套专业主题 |

## 五、非目标范围（明确排除）

1. 媒体播放器 — 本项目只管重命名，不管播放
2. 媒体服务器 — 不提供 DLNA/流媒体功能
3. 下载器 — 不管 BT/PT/HTTP 下载
4. 转码工具 — 不管视频编码转换
5. 字幕制作 — 不管字幕编辑/翻译
6. 媒体库全自动管理 — MVP 不自动监控目录和自动整理
7. CLI 工具 — MVP 只做桌面 GUI

---

## 六、第一阶段不做什么

- 不连接任何在线元数据 API
- 不实现自动监控文件夹变更
- 不实现批量目录结构整理
- 不实现字幕/海报联动重命名
- 不实现 macOS/Linux 适配
- 不支持网络路径/SMB/NFS（除非文件系统层面透明可用）
- 不实现复杂的正则表达式自定义模板编辑器（使用预设字段替换即可）

## 七、UI/UX 初步方向

### 核心设计原则

1. **安全感优先**：用户必须始终清楚软件在做什么、会做什么
2. **可控感**：每个操作都有明确的预览和确认步骤
3. **信息清晰**：原路径 vs 新名称的对比一目了然
4. **风险可视**：低置信度、冲突、非法字符等风险项醒目标记
5. **审美克制**：专业桌面工具风格，不做廉价网页感

### 主流程

```
选择目录 → 扫描 → 分类统计 → 预览对比 → 审核标记 →
人工确认低置信度项 → 冲突检查 → 执行确认 → dry-run/执行 →
查看结果 → 审计日志 → 回滚（如需）
```

### 页面规划（初步）

1. 首页/扫描页 — 选择目录、查看最近任务
2. 扫描结果页 — 分类统计、筛选
3. 重命名预览页 — before/after 表格
4. 人工确认页/面板 — 修改解析结果
5. 执行确认页 — 汇总统计、最终确认
6. 任务历史页 — 历史记录、日志查看、回滚入口
7. 设置页 — 模板、阈值、白名单等

### 视觉方向

- 简洁、高级、低噪音
- 充足留白、清晰层级
- 稳定表格布局
- 明确状态标签
- 危险操作语义明确
- 类似专业桌面工具风格

## 八、整树家谱模式初步方向

项目建设采用"整树家谱模式"：

- 文件夹 = 功能族（如 `scan/`、`rename/`、`rollback/`、`ui/`）
- 子文件夹 = 子功能族（如 `scan/scanner/`、`scan/classifier/`）
- 单文件 = 最小职责（每个文件只做一件事）
- 入口文件 = 薄导出，不承载业务逻辑
- 禁止万能 utils、上帝 service、flat helper、manager 等反模式
- 测试目录镜像源码模块树
- UI 组件按页面族、流程族、组件族、状态族组织

将在阶段 3 输出完整的 `module-genealogy.md`。

## 九、安全底线

1. 默认 dry-run — 不 preview 不执行
2. 执行前多重检测 — 冲突、重名、路径长度、非法字符、权限
3. 低置信度项默认不改名 — 必须人工确认
4. 冲突项阻断执行
5. 二次确认机制
6. 完整 before/after 审计记录
7. 支持按任务回滚
8. 崩溃后可恢复任务状态
9. 开发/测试阶段禁止操作真实媒体目录
