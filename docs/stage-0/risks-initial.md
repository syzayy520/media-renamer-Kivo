# 初始风险清单

> 阶段 0：项目理解与澄清
> 项目：media-renamer-Kivo
> 日期：2026-06-08

---

## 风险等级定义

| 等级 | 含义 | 行动 |
|------|------|------|
| **HIGH** | 可能造成数据丢失、功能不可用或项目无法交付 | 必须缓解后才能进入下一阶段 |
| **MEDIUM** | 可能影响用户体验、性能或开发效率 | 需制定缓解计划 |
| **LOW** | 影响可控，或发生概率极低 | 记录并监控 |

---

## 一、初始风险清单

---

### R-001：误改名导致用户数据损坏

| 项目 | 内容 |
|------|------|
| **等级** | 🔴 HIGH |
| **触发条件** | 重命名逻辑错误、冲突检测遗漏、权限绕过、执行前检查不完整 |
| **影响范围** | 用户媒体文件名永久更改，可能导致播放器/刮削器无法识别文件 |
| **缓解策略** | 1. 默认 dry-run<br>2. 执行前 10 项安全检查<br>3. 低置信度项强制人工确认<br>4. 冲突项阻断执行<br>5. 二次确认机制<br>6. 完整 before/after 审计日志<br>7. 支持按任务回滚<br>8. 测试使用 sandbox fixtures<br>9. 回滚操作本身也记录审计 |
| **阻塞阶段 1** | 否（缓解策略已纳入需求设计，需在阶段 3/5 验证实现） |

---

### R-002：回滚失败导致文件无法恢复

| 项目 | 内容 |
|------|------|
| **等级** | 🔴 HIGH |
| **触发条件** | 回滚时 afterPath 不存在、beforePath 已被占用、权限变化、文件系统错误 |
| **影响范围** | 已改名文件无法恢复为原名，用户需手动处理 |
| **缓解策略** | 1. 回滚前检测 afterPath 是否仍存在<br>2. 回滚前检测 beforePath 是否可用<br>3. 冲突时暂停回滚并报告<br>4. 回滚操作持久化记录<br>5. 支持部分回滚（成功项恢复，失败项报告）<br>6. 不允许覆盖已有文件 |
| **阻塞阶段 1** | 否（需在阶段 1 需求中明确回滚失败场景的处理策略） |

---

### R-003：Windows 路径长度限制导致改名失败

| 项目 | 内容 |
|------|------|
| **等级** | 🔴 HIGH |
| **触发条件** | 目标路径超过 Windows 默认 260 字符限制（MAX_PATH） |
| **影响范围** | 部分文件改名失败，可能导致文件操作异常 |
| **缓解策略** | 1. 扫描阶段检测路径长度<br>2. 预览阶段标记超长路径<br>3. 执行前阻断或警告<br>4. 考虑启用长路径支持（注册表 + manifest）<br>5. 模板设计时避免过长字段组合 |
| **阻塞阶段 1** | 否（需在需求和技术方案中明确处理方式） |

---

### R-004：整树家谱模式腐化

| 项目 | 内容 |
|------|------|
| **等级** | 🔴 HIGH |
| **触发条件** | 赶进度时创建万能 utils/helper/manager；业务逻辑扩散到 UI 组件；模块边界被模糊 |
| **影响范围** | 代码维护性下降，架构退化，后续迭代成本飙升 |
| **缓解策略** | 1. 每轮实现前检查家谱树<br>2. 每轮审计必须检查结构<br>3. 发现违反立即 BLOCKED<br>4. 阶段 3 输出 module-genealogy.md 作为基准<br>5. 禁止跳过结构检查的质量闸门 |
| **阻塞阶段 1** | 否（需在阶段 3 建立完整家谱树基准） |

---

### R-005：文件名解析准确率不足

| 项目 | 内容 |
|------|------|
| **等级** | 🟡 MEDIUM |
| **触发条件** | 非标准命名、混合语言、少见格式、用户自定义命名习惯 |
| **影响范围** | 大量文件标记低置信度，人工确认工作量大，用户不满意 |
| **缓解策略** | 1. 建立 40+ 样例基准集覆盖常见场景<br>2. 解析规则优先级和组合策略<br>3. 低置信度不自动改名<br>4. 人工确认 UI 设计高效<br>5. 支持用户手动修改解析结果<br>6. V1 联网刮削提升准确率 |
| **阻塞阶段 1** | 否（样例基准集在阶段 1 建立） |

---

### R-006：大批量文件扫描/预览性能问题

| 项目 | 内容 |
|------|------|
| **等级** | 🟡 MEDIUM |
| **触发条件** | 单次扫描 5000+ 文件，UI 渲染卡顿，扫描耗时长 |
| **影响范围** | 用户体验差，可能 UI 假死 |
| **缓解策略** | 1. 扫描异步执行，UI 不阻塞<br>2. 虚拟滚动处理大列表<br>3. 扫描进度反馈<br>4. 支持取消扫描<br>5. 性能测试覆盖 10,000 文件场景 |
| **阻塞阶段 1** | 否（需在需求中明确性能目标） |

### R-008：命名模板灵活性与复杂度平衡

### R-UI-003：大列表渲染性能导致 UI 卡顿

| 项目 | 内容 |
|------|------|
| **等级** | 🟡 MEDIUM |
| **触发条件** | 10,000+ 文件渲染在不使用虚拟滚动的列表中；架构目标 100,000 文件 |
| **影响范围** | UI 无响应，用户无法操作 |
| **缓解策略** | 1. 强制使用虚拟滚动（> 100 文件）<br>2. 分页或筛选减少渲染量<br>3. 性能测试覆盖 10,000 及 100,000 文件场景<br>4. 架构设计目标不低于 100,000 文件 |
| **阻塞阶段 1** | 否 |
