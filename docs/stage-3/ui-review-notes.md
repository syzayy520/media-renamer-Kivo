## 二、主题选择评审

### 2.1 候选方案

| 方案 | 优点 | 缺点 | 适用场景 |
|------|------|------|----------|
| 深色主题 | 专业感强、减少视觉疲劳、风险标记醒目 | 部分用户不习惯 | 专业工具、长时间使用 |
| 浅色主题 | 传统、易读、适合明亮环境 | 风险标记不够醒目 | 办公环境、轻量工具 |
| 双主题 | 满足所有用户 | 开发成本翻倍 | 成熟产品 |

### 2.2 决策

**选择深色主题作为 MVP 默认。**

**依据**：
1. **行业对标**：VS Code、Figma、DaVinci Resolve、Plex 均默认深色
2. **用户画像**：媒体收藏者多在暗室环境使用（家庭影院场景）
3. **安全需求**：低置信度（黄色）、冲突（红色）标记在深色背景上更醒目
4. **开发成本**：单一主题降低 MVP 开发量

**备选**：V1 通过 CSS 变量支持浅色主题切换。

## 三、布局评审

### 3.1 候选方案

| 方案 | 描述 | 优点 | 缺点 |
|------|------|------|------|
| 单栏布局 | 全屏表格 | 信息密度高 | 缺乏导航 |
| 侧边栏+内容 | 左侧导航，右侧内容 | 结构清晰 | 占用空间 |
| 顶栏+内容 | 顶部导航，下方内容 | 简洁 | 导航项有限 |

### 3.2 决策

**选择侧边栏+内容布局。**

**依据**：
1. **页面数量**：6+ 页面需要清晰导航
2. **操作频率**：频繁切换扫描/预览/历史
3. **专业感**：侧边栏布局更符合专业工具气质
4. **最小窗口**：1280×800 下侧边栏 240px + 内容区 1040px 足够

## 四、表格设计评审

### 4.1 核心需求

1. **信息密度**：展示原路径、新路径、类型、置信度、状态
2. **对比清晰**：before/after 一目了然
3. **风险可视**：低置信度、冲突项醒目标记
4. **大批量**：支持 10,000+ 行虚拟滚动

### 4.2 表格列设计

| 列 | 宽度 | 内容 | 对齐 |
|----|------|------|------|
| Checkbox | 40px | 复选框 | 居中 |
| 类型 | 80px | 媒体类型标签 | 居中 |
| 原文件名 | flex | 完整路径 | 左对齐 |
| → | 30px | 箭头图标 | 居中 |
| 新文件名 | flex | 新文件名 | 左对齐 |
| 置信度 | 100px | 进度条+数值 | 居中 |
| 状态 | 100px | 标签 | 居中 |
| 操作 | 80px | 按钮 | 居中 |

### 4.3 行状态样式

| 状态 | 背景色 | 左边框 | 说明 |
|------|--------|--------|------|
| 就绪 | 透明 | 无 | 可执行 |
| 低置信度 | rgba(255, 167, 38, 0.1) | 3px 橙色 | 需确认 |
| 冲突 | rgba(239, 83, 80, 0.1) | 3px 红色 | 需处理 |
| 已跳过 | rgba(160, 160, 160, 0.1) | 3px 灰色 | 用户跳过 |
| 选中 | rgba(79, 195, 247, 0.1) | 无 | 已选中 |

### 4.4 虚拟滚动方案

```typescript
// 使用 react-window 或 @tanstack/react-virtual
import { useVirtualizer } from '@tanstack/react-virtual';

function FileTable({ items }: { items: RenamePreviewItem[] }) {
  const parentRef = useRef<HTMLDivElement>(null);

  const virtualizer = useVirtualizer({
    count: items.length,
    getScrollElement: () => parentRef.current,
    estimateSize: () => 48, // 行高 48px
    overscan: 10, // 预渲染 10 行
  });

  return (
    <div ref={parentRef} className="h-[600px] overflow-auto">
      <div style={{ height: `${virtualizer.getTotalSize()}px` }}>
        {virtualizer.getVirtualItems().map((virtualRow) => (
          <div
            key={virtualRow.key}
            style={{
              position: 'absolute',
              top: 0,
              left: 0,
              width: '100%',
              height: `${virtualRow.size}px`,
              transform: `translateY(${virtualRow.start}px)`,
            }}
          >
            <FileTableRow item={items[virtualRow.index]} />
          </div>
        ))}
      </div>
    </div>
  );
}
```

## 五、路径对比设计

### 5.1 需求

用户需要快速识别文件名的变化部分。

### 5.2 设计方案

```
原文件名：[SubGroup] Attack on Titan S04E01 [1080p][HEVC].mkv
新文件名：Attack on Titan - S04E01 - The Other Side of the Sea.mkv
```

### 5.3 高亮策略

- **删除部分**（红色删除线）：`[SubGroup]`, `[1080p]`, `[HEVC]`
- **新增部分**（绿色背景）：`- S04E01 -`, `The Other Side of the Sea`
- **不变部分**（默认色）：`Attack on Titan`, `.mkv`

### 5.4 实现

```typescript
function PathDiff({ original, newName }: { original: string; newName: string }) {
  const diff = computeDiff(original, newName);

  return (
    <div className="font-mono text-sm">
      {diff.map((part, i) => {
        if (part.type === 'removed') {
          return <span key={i} className="text-red-400 line-through">{part.text}</span>;
        }
        if (part.type === 'added') {
          return <span key={i} className="text-green-400 bg-green-400/10">{part.text}</span>;
        }
        return <span key={i}>{part.text}</span>;
      })}
    </div>
  );
}
```

## 六、确认流程评审

### 6.1 安全设计原则

1. **不可逆操作必须二次确认**
2. **明确告知后果**
3. **提供回退路径**

### 6.2 执行确认弹窗

```
┌─────────────────────────────────────────────────────┐
│ ⚠️ 确认执行重命名                                    │
├─────────────────────────────────────────────────────┤
│                                                     │
│  即将对以下文件执行重命名操作：                        │
│                                                     │
│  ✅ 将改名：120 个文件                                │
│  ⏭️ 跳过：5 个文件                                   │
│  ⚠️ 需确认：3 个文件（低置信度）                      │
│  ❌ 冲突：2 个文件                                    │
│                                                     │
│  此操作将修改真实文件名，可通过任务历史回滚。           │
│                                                     │
├─────────────────────────────────────────────────────┤
│                                                     │
│  [取消]                              [确认执行改名]  │
│                                      (红色按钮)      │
└─────────────────────────────────────────────────────┘
```

### 6.3 确认按钮设计

- **Primary（蓝色）**：正常操作（扫描、预览）
- **Danger（红色）**：不可逆操作（执行改名、回滚）
- **Ghost（透明）**：轻操作（筛选、排序）
- **Disabled（灰色）**：有冲突/低置信度时禁用执行

## 七、反馈设计

### 7.1 Toast 通知

| 类型 | 颜色 | 用途 | 持续时间 |
|------|------|------|----------|
| success | 绿色 | 操作成功 | 3秒 |
| error | 红色 | 操作失败 | 5秒 |
| warning | 橙色 | 警告信息 | 4秒 |
| info | 蓝色 | 信息提示 | 3秒 |

### 7.2 进度反馈

- **扫描**：进度条 + 文件计数 + 当前文件名
- **执行**：进度条 + 成功/失败计数
- **回滚**：进度条 + 回滚计数

### 7.3 空状态

| 场景 | 提示文案 | 操作 |
|------|----------|------|
| 未扫描 | 请选择媒体目录开始扫描 | [选择目录] |
| 扫描完成无视频 | 未发现视频文件 | [重新选择] |
| 无低置信度项 | 所有项目置信度足够高 | - |
| 无历史任务 | 暂无任务记录 | - |
